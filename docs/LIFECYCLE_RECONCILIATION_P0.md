# P0｜決済履歴を含む追加約定の再照合（DEMOモック限定）

## 実装範囲と安全境界

`fxjev/lifecycle_reconciliation.py` に `reconcile_late_demo_lifecycle()` を追加した。最終確定したDEMOのエントリー注文について、部分決済・全決済が**すでに記録された後**に、新しい模擬エントリー約定が発見された場合を対象とする。外部ブローカー、注文送信、決済実行、LIVEモード、管理者認証は存在しない。

`reviewer_id` / `review_ref` は検証用の任意文字列で、承認者の本人確認ではない。入力証拠の「完全」フラグは実際のブローカー履歴の信頼性を保証しない。

## 訂正に必要な4つの情報

1. **エントリー全約定の模擬証拠**：`ReconciliationProof`。初回注文のID・口座・ロジック・run・モード・最終状態・発注数量は不変。既知約定の累計数量より増加し、注文数量以内であること。
2. **過去の全決済注文と約定**：`HistoricalClose` の配列。DBの `position_close_batches` と `position_close_executions` に保存された注文ID、最終状態、要求/約定数量、実行ID・約定数量、当時の残高をすべて一致確認。過去の決済データを変更しない。
3. **現在の帰属済み建玉**：`OwnedPosition`。注文・口座・run・取引モードが一致し、スナップショットが新しく、すべての受信イベントの後に取得されていること。
4. **永続イベント台帳と保留記録**：`mock_fill_inbox`、`mock_event_holds`、`mock_event_conflicts`。同一ID重複矛盾・誤帰属・受信イベントの証拠漏れがないこと。

## リスク数量の再構成

確定前のエントリー累計を `E_old`、新しい約定累計を `E_new`、元から保存されている決済済数量合計を `C` とすると：

- 既存残高 `R_old = E_old - C` と、決済バッチが記録した各段階の残高が一致すること。
- 新規残高 `R_new = E_new - C` と、最新の帰属建玉スナップショットが一致すること。
- `E_new > E_old`、`E_new <= 元注文数量`。それ以外は拒否。
- 元の `reconciliation_audit`、決済注文・約定監査テーブルは**上書きしない**。
- 新たな `mock_lifecycle_revisions` に旧/新エントリー累計、決済済合計、旧/新残高、模擬レビュアー・照合参照・SHA-256を追記。
- 1つのSQLite `BEGIN IMMEDIATE` 内で、建玉台帳と元注文約定累計の増加・訂正監査・該当イベント保留の削除を一括処理。途中失敗はロールバック。

例：元エントリー6、決済済3、旧残高3。追加約定2が完全な模擬証拠で確認された場合、最新残高5と一致することを条件にエントリー8、決済済3、残高5へ訂正する。過去の決済バッチは不変。

### 取引停止中の取り扱い

追加約定の保留 `mock_event_holds` が残る間、`fxjev/positions.py` の模擬決済証拠による**リスク予約の減少も拒否**するよう補強した。再照合と保留解消後であれば別の新しい模擬決済証拠を確認し残高更新できる。これは実ブローカーの建玉を強制決済・保護する機能ではない。

訂正成功後も起動ゲートは開かない。DEMOで新規予約するなら、独立した `TradingRuntime.approve_demo()` の模擬再承認が必要。

## 本番未対応の必須条件

- **証拠の真正性なし**：現在は任意の呼出元が作成する模擬証拠。実ブローカーの全量注文・約定・建玉履歴と署名・取得完了性が未実装。
- **初回原約定IDの完全保存なし**：最初の`reconciliation_audit`は約定合計とハッシュのみのため、元の約定IDをブローカー監査原本から厳密に再構築できない。
- **実FXの建玉帰属保証なし**：ネッティング口座の決済・建玉の帰属、銘柄/方向、換算単位、証拠金・損失率などは未実装。
- **管理者認証・安全な運用停止/再開なし**：承認文字列は本人認証済みの操作ではない。
- **外部注文送信との原子性・分散実行なし**：ブローカーAPI切断や多ホスト・遅延/欠落イベントを用いた本番相当の障害復旧は未検証。
- P0 PoCには旧 `Ledger` APIからの予約ルートが残り、稼働サービス全体の唯一の発注経路保証は未達。

Jev AIは各ロジックが定義した候補IDを1つだけ返し、説明・確信度・追加数値は返さない。**main反映・本番公開・実口座接続・実売買は別途明示承認まで実行しない。**
