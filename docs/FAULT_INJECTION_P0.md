# P0 強制終了・遅延イベント・再起動の障害注入 PoC

## 対象

実ブローカーを使用せず、SQLite注文予約・建玉残高・UNKNOWN注文の復旧安全性を検証。GitHub Actions は Linux / Python 3.12 で全テストを自動実行する。ネットワーク、FX認証情報、実注文送信は不要。

実装: `fxjev/ledger.py` の `recover_unresolved_intents()`。テスト: `tests/test_fault_injection.py`。

## 強制終了テストの実態

`subprocess.Popen` で**実際に別Pythonプロセス**を起動し、書き込みの完了／未完了をマーカーファイルで同期させた後に `SIGKILL` で停止する。その後、新しいLedgerインスタンスでSQLite状態・予約数量・監査記録・`PRAGMA integrity_check`・`foreign_key_check` を確認する。

- コミット済み予約：SIGKILL後も注文意図とリスク予約が永続化され、同一client IDで再予約できない
- 未コミット予約：トランザクション内の直接SQLで擬似的にステージした予約はロールバックされる
- 未コミットUNKNOWN移行：変更がロールバックされても、後から明示復旧を実行するとUNKNOWNへ変換できる
- コミット済みUNKNOWN：SIGKILL後も口座の新規予約が停止され、別口座は独立
- 未コミット建玉減少：トランザクション内の直接SQLで模擬的に変更した残高はロールバック
- コミット済み部分決済：残高減少と決済監査が永続化され、同じ決済注文IDの再適用を拒否
- SQLiteの書き込みロック保持中にSIGKILL：ロックが解放され、未コミット上限変更が破棄される

**重要な範囲制限**：未コミット予約／建玉のSIGKILLテストは、実メソッドの途中へ強制注入するのではなく、同じSQLiteトランザクション内で直接SQLをステージしている。SQLiteの原子性を検証するもので、ブローカー発注と内部DB更新の分散原子性を証明しない。

## 起動時UNKNOWN復旧

`ledger.recover_unresolved_intents()` は、状態が `reserved` の全注文を1つの `BEGIN IMMEDIATE` トランザクションで `unknown` に移行し、`startup_recovery_audit` へclient IDと記録時刻を保存する。**リスク枠は一切解放しない**。既にUNKNOWNまたは確定済みの注文には変更を加えない。何度呼んでも再度解放・重複監査されない。

この関数はプロトタイプ内で**自動起動されない**。実稼働前に起動管理プロセスが新規注文受付より先に確実に呼び出し、実ブローカーとの注文・建玉照合が完了するまで新規注文を止める実装と受入試験が必須。

## 遅延・順不同イベントの確認

- 不完全な注文・約定・建玉証拠はUNKNOWNのままリスク予約を保持し、その後の完全なモック証拠では確定できる
- すでに確定した注文に遅れて届く別の最終状態は適用されない
- 初回エントリー照合より早く到着した決済証拠は却下され、エントリーが確定した後の再照合で決済残高を反映できる
- 再起動後の重複決済証拠は再適用されず、二重解放が起こらない
- 古い建玉スナップショットは拒否され、新しい整合証拠だけが採用される
- 口座・取引モードを分けた停止は従来どおり
